# V1 实施与验收计划

第一版对客户交付的是 `v1-scope.md` 定义的完整能力，不拆成对外销售的残缺版本。下列阶段是
内部研发顺序：每阶段都形成可验证的纵向切片，但只有全部首版退出条件满足后才允许对外发布。

## 1. 实施原则

- 先验证高风险技术假设，再固化领域模型和第三方组件选择。
- 先建立能力接缝、协议和事实记录，再接具体供应商实现。
- 配置与发布分离；运行只引用不可变版本和快照。
- 数值计算、权限和策略判断使用确定性代码，LLM 只处理理解、规划和文本生成。
- 每阶段同步完成权限、审计、监控、测试、迁移、文档和删除/保留规则，不积累“最后再补”的治理债务。
- 不以演示成功代替异常恢复、并发、权限隔离、成本核对和私有化安装验证。

## 2. 阶段划分

### 阶段 0：架构验证与组件 POC

目标是关闭影响架构的未知项，不建设面向客户的半成品页面。

- 按 `README.md` 的待 POC 表比较 Agent 运行时、模型网关、检索、文档解析和 PDF 方案。
- 固定支持的模型供应商与私有模型协议基线，验证离线环境和代理环境。
- 输出每个组件的版本、许可证、SBOM、资源基线、失败语义、数据持久化位置和替换路径。
- 定义统一运行、调用事实、错误码、SSE 和异步任务契约，并用最小原型验证。
- 恢复依赖漏洞扫描门禁；任何新增高危依赖不得以“POC”名义进入正式基线。

退出条件：待 POC 决策全部有证据和结论；ADR、模块接缝和部署矩阵评审通过。

### 阶段 1：平台骨架与开放边界

- 建立 AI、知识、数据、报表领域模块及薄 `*-api` 接缝。
- 建立业务系统客户端、Scope、凭证轮换、限流、幂等和 `/open-api/v1` 错误契约。
- 接入模型网关的管理、健康检查、模型目录、路由、价格版本和凭证引用。
- 建立统一任务、事件、制品、审计关联 ID 和 Outbox 投递基础。
- 在现有 Vue 管理端增加统一 AI 平台导航与权限点，页面只使用平台 API。

纵向验收：管理员可以安全配置并测试一个模型；业务系统可通过机器凭证调用受保护的测试应用，
且调用、权限、限流和审计链路可追踪。

### 阶段 2：Agent 运行与模型统计

- 完成应用、Agent、Prompt、Skill、Harness 和 Workflow 的草稿、发布、回滚和引用规则。
- 支持流式运行、取消、超时、工具调用、人工介入、检查点、恢复和统一错误分类。
- 建立会话、消息、上下文压缩、长期记忆、Workspace 和制品关联。
- 每次模型调用落不可变事实，支持 Token、延迟、首 Token、错误、成本和预算统计。
- 建立脱敏 Trace、运行详情、调用明细、统计聚合和最小评估集。

纵向验收：一个已发布 Agent 可从管理端和开放 API 稳定运行；进程中断后按策略恢复；统计可与
网关原始记录对账，失败调用也有事实记录。

### 阶段 3：知识库闭环

- 完成知识库、来源、文档版本、解析、切片、Embedding、索引、撤索引和重建任务。
- 完成关键词、向量、混合、过滤、TopK、阈值和重排配置。
- 权限过滤进入召回查询，回答返回可验证引用，并提供独立检索调试页。
- 解析与索引失败可诊断、重试和续跑；文件、数据库与索引状态可以对账。
- 建立检索质量测试集和版本回归报告。

纵向验收：不同权限主体对同一问题只能看到授权文档；文档更新和删除后索引最终一致；无证据时
不会生成虚假引用。

### 阶段 4：数据、MCP 与工具闭环

- 完成数据源、元数据快照、业务术语、关联、指标和查询策略发布。
- 完成结构化查询计划、确定性 SQL 校验/编译、只读执行、资源限制、脱敏和查询审计。
- 完成工具定义/版本、MCP Server、发现快照、健康、凭证引用和副作用等级。
- 完成 HTTP 出站策略、SSRF 防护、重试边界和人工审批节点。
- 建立数据库/MCP 模拟器和真实兼容环境的契约测试。

纵向验收：Agent 可在授权范围内选择指标、查询客户只读 View、调用只读 MCP 工具；任何越界对象、
危险 SQL、未发布工具变化和未批准副作用都被确定性拒绝并审计。

### 阶段 5：自动报表闭环

- 完成报表定义、数据集、模板、版本、调度、运行、制品、发布和 Webhook。
- 指标与表格由确定性查询产生，LLM 只生成解释、风险、建议和摘要。
- 使用可信组件将结构化数据渲染为可视化 HTML；落实转义、CSP、离线资源和制品权限。
- 支持日报、周报的补跑、幂等、版本快照、失败诊断和数据截止时间说明。
- 若阶段 0 选择 PDF，则补充隔离渲染、中文字体、分页和视觉回归；否则明确首版仅交付 HTML。

纵向验收：同一数据快照和模板版本可重现报表；计划重复触发不会产生重复发布；业务系统可异步
查询状态并受权获取制品。

### 阶段 6：运营、评估与私有化收口

- 补齐运行/模型/工具/检索/查询/报表的统一观测、告警、SLO 和诊断入口。
- 完成回归数据集、模型对比、知识检索评估、人工评分和发布前质量门槛。
- 完成模型与租用组件故障演练、备份恢复、索引重建、统计对账和预算熔断。
- 完成离线安装、升级、回滚、许可证、SBOM、配置检查、容量基线和运维手册。
- 执行全部安全、性能、兼容、权限、生命周期和端到端验收。

退出条件：`v1-scope.md` 的全部一级能力通过验收，不存在绕开权限/审计的临时通道，且目标客户
部署拓扑完成一次全新安装与恢复演练。

## 3. 关键 POC 验收矩阵

### 3.1 Agent 运行时

| 项目 | 最低证据 |
| --- | --- |
| 流式与取消 | SSE 顺序稳定；断开与主动取消可终止下游调用并形成最终状态 |
| 工具与结构化输出 | Schema 校验失败可识别；工具异常不会污染会话状态 |
| HITL | 中断点持久化；批准、修改、拒绝后行为可重放和审计 |
| 恢复 | Java 进程在模型前、模型后、工具前后中断均有明确恢复策略 |
| 上下文 | 长会话压缩可配置，原始消息和引用不被覆盖 |
| 隔离 | 两个并发运行的 Workspace、凭证和工具上下文不串用 |
| 依赖 | 完整传递依赖、漏洞、许可证和升级影响报告 |

### 3.2 模型网关

| 项目 | 最低证据 |
| --- | --- |
| 协议覆盖 | Chat、流式、Embedding、Rerank 和计划供应商逐一实测 |
| 计量 | Token、缓存 Token、首 Token、总耗时、错误和实际模型与供应商记录可核对 |
| 路由 | 主备、超时、限流、熔断和能力不等价时的显式失败可验证 |
| 动态配置 | 模型、端点、凭证版本和策略变更无需重启业务应用，且可回滚 |
| 故障语义 | 网络失败、供应商限流、内容拒绝、上下文超限和格式错误映射稳定 |
| 私有部署 | 离线镜像、资源占用、数据外发开关、日志脱敏和许可证满足交付要求 |

### 3.3 检索服务

| 项目 | 最低证据 |
| --- | --- |
| 检索质量 | 中文关键词、向量、混合与重排在固定测试集上对比 |
| 权限与过滤 | 业务系统、用户、知识库、文档和元数据过滤在召回阶段生效 |
| 一致性 | 更新、软删、失败重试和全量重建后能与 MySQL 事实对账 |
| 运维 | 备份恢复、容量增长、批量导入、延迟和资源基线有实测数据 |
| 可替换性 | 核心领域不依赖厂商 DTO，替换适配器的契约测试可以复用 |

## 4. 质量门禁

### 4.1 延续现有门禁

- 后端 `mvn verify`、单元测试、集成测试、启动烟测、JaCoCo、Spotless 和 ArchUnit。
- 前端类型检查、Lint、单元测试、构建和核心流程 E2E。
- 数据库迁移正向执行、升级兼容、唯一性/外键/状态约束和数据生命周期检查。
- API 错误映射、鉴权、权限点、分页、幂等和敏感字段测试。

### 4.2 新增 AI 平台门禁

- Java、Node、Python、容器的依赖漏洞、许可证、SBOM 和版本固定检查。
- OpenAPI 契约生成与破坏性变更检测；SSE 事件和 Webhook 签名契约测试。
- 模型网关、Agent 运行时、MCP、检索和查询执行器的适配器契约测试。
- 至少一个可控模型和一个真实目标模型的端到端回归；外部服务不可用时测试仍可确定运行。
- Prompt/Skill/Workflow 发布校验、快照不可变、引用保护、删除和保留策略测试。
- Prompt 注入、越权检索、SSRF、危险 SQL、XSS、凭证泄漏和重放攻击的安全用例。
- 报表 HTML 快照、浏览器渲染和关键图表视觉回归；选择 PDF 时增加分页回归。
- Token/成本统计与网关事实对账，聚合结果可从调用明细重算。
- 备份恢复、Redis 丢失、索引重建、Worker 崩溃、模型超时和事件重复投递演练。

门禁必须以 CI 脚本、测试或架构规则执行；只写在文档中的约束不算已落实。

## 5. 首版发布退出条件

只有同时满足以下条件，才可声明 V1 可交付：

- `v1-scope.md` 12 个一级能力逐项有负责人签署的验收记录。
- 管理端和开放 API 使用相同领域能力，不存在仅供演示的旁路。
- 模型、Agent、工具、知识、查询和报表的版本快照能关联到每次运行。
- 权限、审计、调用统计、Token、成本和制品链路可以从入口追踪到结果。
- 核心故障可恢复，异步操作可幂等重试，没有只存在于 Redis 或进程内的关键事实。
- 目标私有化环境完成离线全新安装、升级、回滚、备份恢复和容量验证。
- 无未处置的严重/高危安全问题；有时限的例外具备书面范围、补偿控制和负责人。
- 用户手册、管理员手册、开放 API 文档、部署手册、升级手册和故障排查文档齐全。

## 6. 进入编码前的设计冻结点

编码启动前至少完成以下确认：

1. 评审并接受目标架构 ADR、V1 范围、模块边界、安全边界和开放 API 入口。
2. 完成阶段 0 POC，并关闭 `README.md` 中的组件选择项。
3. 明确首批支持的模型协议、客户数据库类型、文档格式和报表交付格式。
4. 明确正文观测、知识文档、会话、查询结果和报表制品的默认保留期。
5. 明确业务系统机器认证首选方案及客户不能使用该方案时的兼容边界。
6. 将第一阶段拆成可独立验证的需求和迁移，每项写明验收、非目标和回滚方式。

团队规模、目标客户环境和性能基线尚未确认，因此本文不承诺工期。工期应在阶段 0 取得组件
实测数据和首批客户边界后估算，避免用未经验证的框架能力推导日期。
