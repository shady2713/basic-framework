# ADR 0008：企业 Agent 中台目标架构

- 状态：拟议，待架构评审

## 上下文

本仓库将作为面向私有化客户的企业 Agent 中台产品基座。每个客户独立部署一套实例，
实例内可以接入多个业务系统、部门、项目、Agent、知识库和模型，但不提供跨客户共享的
多租户 SaaS 能力。

第一版对外发布必须覆盖 Agent、模型、知识、数据、工具、报表、开放接口、观测评估与
私有化运维的完整闭环。内部研发可以分阶段验收，但不能以删除一级能力作为首版交付手段。

现有 ADR 0006 将外部开放 API 定义为“不提供”。该约束仍描述当前已实现产品；本 ADR
提议目标产品新增受控的机器到机器开放 API。开放 API 上线前必须完成独立认证、权限、
限流、兼容、审计和威胁模型控制，不得复用管理后台用户会话作为业务系统凭证。

## 决策

1. 现有 Spring Boot 3 / Java 17 后端和 Vue 3 / TypeScript 管理端是产品控制面与唯一前端。
2. Spring AI Alibaba 仅作为 `AgentRuntime` 的首个 Provider，通过能力接缝接入；业务模块
   不直接暴露或持久化其框架类型。
3. 模型网关、向量检索和私有模型可以独立部署为数据面组件。浏览器不直接访问这些组件，
   管理、统计和诊断均经 Java 控制面统一授权与聚合。
4. 第一版保持单租户，不新增 `tenant_id`、租户路由、套餐、租户配额或跨租户管理假象。
5. 业务系统使用独立机器凭证访问 `/open-api/v1/**`；管理端继续使用 `/admin-api/**`，
   两套身份、权限和限流边界不得混用。
6. 确定性计算与非确定性生成分离。指标、金额、进度、成本和统计由受控代码或 SQL 计算；
   LLM 只解释已验证的数据或输出受约束的结构化结果。
7. 模型调用明细和版本化价格规则是用量与成本统计的事实源；Agent Trace 是执行解释源，
   二者通过 requestId、traceId、applicationId、agentId、sessionId 关联。
8. HTML 报表只能由受信模板和结构化图表定义生成；模型输出不得作为未清洗 HTML、脚本、
   SQL、文件路径或 Shell 命令直接执行。
9. 新横切能力继续遵循 starter 能力接缝；新业务能力按薄 API 模块协作，ArchUnit 保持依赖
   方向可验证。

## 后果

- 产品能力、权限、数据与升级权留在本仓库；外部组件可以替换而不改变前端和业务 API。
- 第一版仍有较大的领域开发量，但不需要重建现有认证、数据权限、任务、文件、审计、MQ、
  Flyway 和工程门禁。
- 开放 API、主动网络访问、模型凭证、MCP、数据库查询、知识文档和生成报表扩大了信任边界；
  实现前必须按 `docs/ai-platform/security-and-deployment.md` 修订当前威胁模型和数据分级目录。
- Spring AI Alibaba、模型网关和向量服务的具体产品与版本由受控 POC 决定，领域模型不依赖
  候选组件的私有字段。
